🏗️ ARCHITECTURE OVERVIEW

COMPRESSION:
  Input File → Tokenize → Analyze Frequency → Calculate Savings
    → Build Dictionary → Write Header → Replace Words → Output .cmp

DECOMPRESSION:
  Input .cmp → Parse Dictionary → Build Mapping → Find Tokens
    → Expand Tokens → Restore Words → Output Original

KEY ALGORITHM:
  • Only words with frequency >= 2 are candidates
  • Each word's savings calculated: 
    Savings = (Original Cost) - (Token Cost + Dictionary Overhead)
  • Only include word if Savings > 0
  • Perfect round-trip guaranteed

💡 KEY INSIGHTS

Rule 1: Profit-Based Compression
  "Do not replace words merely because they repeat.
   Replace only when it saves space (positive net savings)."

Rule 2: Three-Type Comments
  Every significant code block has:
  1. WHAT THIS DOES - what it accomplishes
  2. WHY AND INTENT - why this design was chosen
  3. Inline clarifications - complex logic details

Rule 3: Perfect Round-Trip
  Decompress(Compress(original)) == original
  Always and perfectly guaranteed.

Rule 4: File Format Structure
  Dictionary first → ===END_DICT=== → Compressed Body
  This order is critical for correct decompression.
